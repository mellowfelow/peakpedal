# Peak Pedal — Technical & SEO Audit

**Date:** 2026-09-08 · **Scope:** WebForge Mode 4 (Technical + On-Page SEO + AI-Visibility + Agent-Ready), static tier (codebase + `npm run build`), a live crawl of `https://www.peakpedal.org`, and field data from Google Search Console, Bing Webmaster Tools and Semrush (pulled 2026-09-08).

---

## Verdict

The build is technically sound — clean HTML, valid schema, one H1 per page, full agent-ready file set, correct security headers, correct Web3Forms method, and compliant EAPC framing throughout. No manual action, no security issue, sitemap healthy.

But this is a **5-week-old site with zero domain authority**. GSC: 20 clicks / 6,990 impressions / 0.3% CTR / **average position 43.8**. Bing: 1 click. Semrush UK: **Authority Score 0, ~1 organic visit/month, 0 backlinks**. The dominant constraint is off-site — with no links, the head terms (`electric mountain bike`, 12,100/mo) are unreachable no matter how good the pages are.

Within what the build *can* control, three things are capping it and the field data now proves each:

1. **Forms silently discard every submission on the live site** (C1).
2. **Thin, templated product/accessory content** (H5) — Google has left **53 of 217 URLs "Discovered – currently not indexed"** (never crawled): ~26 product pages, ~22 accessory pages. Bing has indexed only 81/217.
3. **Orphaned commercial category pages** (H6) — `/bosch-electric-mountain-bikes/` and `/electric-mountain-bikes-under-2000/` are in that not-indexed 53 *because nothing links to them*.

Plus Google Merchant Listings is actively flagging the missing `shippingDetails` / `hasMerchantReturnPolicy` (now **H7**).

### Sequence to work in

1. **C1** — set the Web3Forms key (5 min; unblocks the only reason the site exists).
2. **H5 + H6 together** — expand product/accessory copy *and* wire the internal links in one pass, then request indexing on the 53 in GSC. Highest-leverage block.
3. **H2 / H7 / H3 / H4** — title, schema and share-image template fixes; one PR touching `generateMetadata` + the schema builders.
4. **M8–M12 + M16** — performance, freshness, and the inert IndexNow submission.
5. **Off-site** — not a code task, but nothing moves the head terms without it: digital PR, brand directories, real social profiles, supplier/brand-partner links.

## Critical

### C1 — Contact and order forms send nothing on the live site
`FORMS.web3formsKey` is `''` in `src/config/site.js`, so `WebForm.jsx`'s key-pending branch is active **in production**: every contact-form and order-form submission calls `router.push(thankYouPath)` and is discarded. No email is sent anywhere. WhatsApp and the Tawk.to widget are the only working contact channels right now.
**Fix:** create a Web3Forms access key for `info@peakpedal.org`, set `FORMS.web3formsKey`, rebuild, redeploy. Then submit all three forms end-to-end.

## High

### H2 — Product page titles are 80–90 characters (all 124 product pages)
`products/[slug]/page.jsx` builds `title: "${product.name} | ${product.brand} Electric Mountain Bike"`, then the root layout's `title.template` appends ` | Peak Pedal`. Result on the live site:
```
Specialized Turbo Levo 4 Expert Carbon | Specialized Electric Mountain Bike | Peak Pedal   (86 chars)
```
Brand name appears twice; Google truncates around 60. **Fix:** drop the redundant middle clause and let the template add the brand — e.g. `title: "${product.name} — ${product.brand} eMTB"` → `"… | Peak Pedal"` at ~45–60. Same tightening for brand-page titles (`"{Brand} Electric Mountain Bikes UK — Full Range | Peak Pedal"` runs 61–62 for longer names) and the main shop page (`"Electric Mountain Bikes UK | Shop the Full Range | Peak Pedal"`, two pipes).

### H3 — Social share image is `/images/placeholder.svg` sitewide
Homepage, every category page, every brand page and every blog post set `openGraph.images` / `twitter.images` to the placeholder SVG. SVG is not a supported social-card format — links shared to WhatsApp, Facebook, X, LinkedIn, Slack and iMessage render with no preview image, and it weakens Google Discover eligibility. Product pages correctly use the real product `.webp`.
**Fix:** add a real 1200×630 PNG/JPG `app/opengraph-image.png` (brand default — logo + tagline + hero crop), and per-type images for the main category pages. Wire `twitter` to the same file.

### H4 — Twitter Card tags fall back to generic site defaults on non-product pages
On the homepage the live output is `twitter:title = "Peak Pedal | Ride Further. Climb Harder."` while `og:title` is the page-specific string. Category and blog `generateMetadata` set `openGraph` but not `twitter`, so X/Twitter shows the layout default.
**Fix:** set `twitter` alongside `openGraph` in each `generateMetadata` (or a small helper).

### H5 — Thin, near-duplicate product descriptions across 124 pages
Every product body is one generated sentence from `describe()`:
```
The Trek Rail 5 is a full-suspension enduro eMTB from Trek, running a Bosch Performance CX motor with 160/150mm of travel.
```
Pages differ only by name/brand/motor/travel. No unique copy, no ride context, no comparison, no per-model FAQ. **Field proof:** ~26 product pages and all ~22 accessory pages sit in GSC's "Discovered – currently not indexed" bucket — Google found them in the sitemap and decided they weren't worth crawling. Bing has indexed only 81/217 URLs. Accessory pages are worse still — one templated `accessoryBlurb()` sentence each.
**Fix:** 100–200 words of genuinely per-model copy (who it's for, how it sits vs its siblings, what the travel/motor choice means) plus 2–3 model-specific FAQ entries feeding `FAQPage` schema; same treatment (shorter) for accessories. The spec table is already there and good. After deploy, use GSC → Pages → the not-indexed list → Validate Fix, and Request Indexing on the highest-value URLs.

### H6 — Commercial category pages orphaned from global navigation
No link from nav **or** footer to: `/electric-mountain-bike-sale/`, `/electric-mountain-bikes-under-2000/`, `/electric-mountain-bikes-under-3000/`, `/off-road-electric-bikes/`, `/bosch-electric-mountain-bikes/`, `/shimano-electric-mountain-bikes/`, `/dji-avinox-electric-mountain-bikes/`. Combined that's roughly 2,300 searches/month sitting behind pages that receive almost no internal PageRank (only `sitemap.xml` and `llms.txt` point at them). **Field proof:** `/bosch-electric-mountain-bikes/` and `/electric-mountain-bikes-under-2000/` are both in GSC's not-indexed 53 — a page with a real keyword target that Google won't crawl because nothing links to it.
**Fix:** add a footer column "Shop by price" + "Shop by motor"; add contextual links from the matching blog posts (`bosch-vs-shimano-emtb-motor` → both motor hubs, `best-electric-mountain-bikes-under-2000` → the `/under-2000/` filter) and from category intros. Consider building the deferred `/brands/` hub as the pattern.

### H7 — Product `Offer` is missing `shippingDetails` and `hasMerchantReturnPolicy` (Google is flagging it)
GSC → Merchant listings shows **0 invalid, 8 valid**, with two "Improve item appearance" issues on **all 8** detected items: *Missing field "hasMerchantReturnPolicy" (in "offers")* and *Missing field "shippingDetails" (in "offers")*. Both are real, stateable facts — free UK shipping, and a returns policy already exists at `/refund/`. Their absence suppresses the shipping/returns annotations in product results and blocks free Merchant listing eligibility.
**Fix:** in `products/[slug]/page.jsx` add `shippingDetails` (`OfferShippingDetails`, `shippingRate: 0`, `shippingDestination: GB`), `hasMerchantReturnPolicy` (`MerchantReturnPolicy` from the `/refund/` terms), and a rolling `priceValidUntil`. Was M13; promoted because GSC is actively reporting it.

## Medium

### M7 — `prefers-reduced-motion` is not handled anywhere; hero autoplays
`grep -rn "prefers-reduced-motion" src/` → nothing. `HeroSlider.jsx` runs `setInterval(..., 6000)` with a cross-fade and no pause control (the dots change slide but don't stop rotation). WCAG 2.2.2 (Pause/Stop/Hide) and the WebForge "no autoplay carousel" rule both apply.
**Fix:** gate the interval behind `window.matchMedia('(prefers-reduced-motion: reduce)').matches`, add a global `@media (prefers-reduced-motion: reduce){ *{animation-duration:.01ms!important;transition-duration:.01ms!important} }`, and add a visible pause toggle (or drop auto-advance).

### M8 — Tawk.to widget is preloaded and loaded `afterInteractive` on every page
Live head contains `<link rel="preload" href="https://embed.tawk.to/6a70…" as="script">` and `ChatHub.jsx` uses `strategy="afterInteractive"`. The chat bundle competes with homepage LCP/TBT on first load.
**Fix:** `strategy="lazyOnload"`, or load on first scroll / interaction / 3s idle. Drop the preload.

### M9 — Below-the-fold product image preloaded on the homepage
`page.jsx` marks the first `ProductCardHome` `eager={i === 0}`, producing `<link rel="preload" as="image" href="/images/cube-stereo-hybrid-one44-race.webp">`. That card is well below the fold and not the LCP element; it competes with the hero preload.
**Fix:** remove the `eager` flag on the featured grid — the hero is the LCP.

### M10 — Single flat sitemap, no image sitemap
`app/sitemap.js` emits one `sitemap.xml` with 217 `<loc>` entries and no `<image:image>`. Fine for crawling at this size, but WebForge v9's split + image-aware sitemap would surface ~90 real product photos to Google Images.
**Fix:** `generateSitemaps()` split (pages / products / categories / blog) with `<image:image>` on product and accessory entries.

### M11 — Article schema has no dates; no page emits `og:updated_time`
`blog/[slug]/page.jsx` `Article` schema omits `datePublished`, `dateModified` and `image`. No freshness signal anywhere.
**Fix:** add real `date` / `updated` fields to each `POSTS` entry, render them into the `Article` schema and as `og:updated_time`, and show a visible "Updated" line on the post.

### M12 — Homepage Organization schema is missing cheap entity fields
`storeSchema` in `page.jsx` has no `telephone`, no `email` / `contactPoint`, no `logo` / `image`, no `foundingLocation` object; `sameAs: []` is emitted as an empty array (drop the key instead). `foundingDate` is correctly omitted (not fabricated).
**Fix:** add `telephone`, `email`, `logo` (absolute URL to a real PNG), and a `foundingLocation` `{ "@type": "Country", "name": "United Kingdom" }`. Populate `SITE.social.sameAs` once real profiles exist.

### M13 — IndexNow key is served but nothing submits URLs
`scripts/gen-agent-files.mjs` writes `public/2b9665d59fefb51aecc603a7dceae7f8.txt` and the layout emits the `indexnow-key` meta, and the key file returns `200 text/plain` live — but **no code ever pings `api.indexnow.org`** on deploy or content change (static site, no submission step). Bing Webmaster Tools' #1 recommendation (High severity) is "Set up IndexNow". Installed but inert.
**Fix:** add a post-deploy step (Vercel deploy hook, or a `postbuild` script gated to production) that POSTs the changed URLs — or just the sitemap URL — to `https://api.indexnow.org/indexnow` with `{ host, key, keyLocation, urlList }`. Bing + Yandex pick it up immediately.

### M14 — Listing pages carry no `ItemList` / `CollectionPage`
30+ category and brand pages emit only `BreadcrumbList` (+ `FAQPage` where present). An `ItemList` of the products shown is a straightforward add and helps Google understand these as product-listing pages.

### M15 — `docs/PROJECT.md` and `docs/keyword-map.md` are stale
PROJECT.md still says "78 SKUs", "every product uses a shared placeholder", "WhatsApp link only — no widget". Live reality: 124 SKUs, ~90 real product photos, a Tawk.to widget deployed, domain/GSC/FAQ fixes already shipped. keyword-map.md says 125 products and lists already-completed "critical fixes".
**Fix:** reconcile both docs to the live state so the next session doesn't act on wrong facts. (This audit's findings are the current truth.)

## Low / housekeeping

- **L16** — Extensionless `.well-known/*` files (`api-catalog`, `ucp`, `openid-configuration`, `oauth-authorization-server`) serve as `application/octet-stream` on Vercel. Known Vercel platform limitation; isitagentready is lenient here. Accept, or add a `rewrites`-to-function shim.
- **L17** — Markdown content negotiation (WebForge V5 `middleware.js`) not implemented — `Accept: text/markdown` returns HTML. Worth 1 point on isitagentready "Content"; optional.
- **L18** — Apex → www is `308`, not `301`. Google honours both; some third-party auditors flag it. Vercel default.
- **L19** — HSTS is `max-age=63072000` with no `includeSubDomains` / `preload`.
- **L20** — Homepage brand-tile logos and the product-page main gallery image use a raw `<img>`, not `next/image` — the product LCP image gets no responsive `srcset` / AVIF.
- **L21** — `HOME_FAQS` "Can I buy on finance?" answers "coming soon" while `/finance/` is live and in the nav. Align the copy.
- **L22** — `llms.txt` lists `/privacy/`, `/terms/`, `/refund/`, `/shipping/` under "Excluded" but they're in `sitemap.xml`. Pick one (keep them indexable; drop from the llms "Excluded" list).
- **L23** — `robots.txt` `Content-Signal:` line sits between crawler groups rather than inside one. Harmless; tidy in `robots.txt/route.js`.
- **L24** — `scripts/crosscheck.mjs` is a reduced subset of the WebForge crosscheck: no compliance-term scan, no sitemap validation, no internal-link / orphan scan, no duplicate-body-content hash, no accessibility or performance gate. Extend it so regressions on H5/H6/M7 get caught automatically.
- **L25** — Untracked `files.zip` in the repo root — remove or gitignore.

- Hero uses `next/image` with responsive `srcSet` + `rel=preload` + AVIF/WebP; system font stack (no render-blocking font chain); one CSS file, no `@import`.
- Mobile: `overflow-x:hidden` + `max-width:100vw` guards, viewport meta, hamburger nav, `:focus-visible`, `.skip-link:focus`, `.mega-dropdown:focus-within`.
